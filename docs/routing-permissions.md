# 子任务路由的统一权限

打开 **设置 → 子任务路由 → 执行权限**，选择并保存：

| 选项 | Codex harness | Claude harness |
| --- | --- | --- |
| 请求批准 | 工作区可写、人工审批 | `default` |
| 帮我审批 | 工作区可写、`auto_review` | `auto` |
| 完全访问 | `full-access`、`deny_all` | `bypassPermissions` |
| 沿用会话权限 | 保留原有会话与子任务的权限约束 | 保留原有约束 |

显式选择的档位统一用于路由模式的主执行模型和子 agent，包括新建、恢复和跨 harness
交接。保存后下一次运行生效，正在运行的任务保持启动时的授权。主模型不变。
输入框显示统一档位，修改入口集中在路由设置；指定模型模式仍使用独立会话权限。

这些是 harness 的原生语义：完全访问仍受服务强制规则、系统权限和外部登录授权约束。
原生客户端拒绝该档位时会报告失败，不静默切换档位。ACP 没有对应的统一权限语义，
显式统一档位下不会参与路由；跨后端委派仍需要已有配置授权。
子 agent 的人工审批通过当前主任务的审批界面回传，取消后不重试。

独立评估器始终只读，不会因执行权限选择获得额外工具权限。API 主模型自身的 Cleo
工具策略、订阅聊天的只读运行策略保持原有边界；统一档位用于其委派的可执行 harness。
安全重放仍限制为只读 Codex，最多升级一次，不扩大已有副作用。

配置示例（`routing-permissions.json`，也可在界面保存；旧版本会忽略此文件）：

```json
{
  "preset": "full"
}
```

旧配置缺少此文件时默认为 `inherit`，不会自动扩大权限。
权限映射、审批回传、取消和委派验证使用本地 fake provider，不调用付费模型。
