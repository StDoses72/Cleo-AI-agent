# 0018. 历史翻页只沿读者的方向推进；视野内的内容只在读者到达边缘时让位

- **Status**: Accepted
- **Date**: 2026-11-25

## Context

Issue #202：一直向下滚动聊天历史，视图反复弹回同一段旧消息，较新的消息只闪过一帧。

历史窗口的上限按原始条目计（`ui/src/timeline-cache.ts` 的 `MAX_TIMELINE_ITEMS`，500 条），而界面把同一轮里连续的思考和工具调用折叠成一行（`groupTimelineItems`）。一轮里有 502 条过程记录时，这一行单独就能占满窗口：窗口折叠后只剩几行，两端同时落在预取范围内，而且缓存放不下这一行两侧的正文。在这种窗口上，当时的代码有五处会让视图自己动起来：

- `Conversation.trackScrollPosition` 先判断顶部、不看滚动方向。向下翻页后窗口变短，顶部立刻进入预取范围，于是请求更早的一页，窗口退回原处。
- `VirtualTimeline` 把「这次渲染之后位置变了」一律当作读者滚动。内容变短时浏览器会把滚动位置收回去，这个位移同样触发了翻页判断。
- 内容不足一屏时的自动补页固定先向后、再向前，不看读者的方向。向上翻页进入短窗口后，它把窗口又拉回下方：用合成数据复现时，向上滚永远到不了第一条消息。
- 折叠行和工具调用串的 id 取自窗口内的第一条记录。窗口首端被裁掉后 id 变了，同一行被当成新的一行：位置锚点丢失，展开状态和已测高度作废。
- 读者在窗口顶端继续上滚时，滚轮输入会清掉位置锚点，而视口没有移动，不会重新记录；这时旧页插入，视图跳过整整一页。任务收尾时的后台刷新（`history.load("latest", …)`）用最新一页替换整个窗口，停在更早一页的读者正在读的内容随之消失。

## Decision

- **翻页只沿读者最后一次移动的方向进行。** 方向由滚轮输入立即确定（视口动不了时同样生效），其他方式的滚动（滚动条、键盘）取读者造成的位移的符号。向下时只加载后一页，向上时只加载前一页；换向从下一次输入起生效。打开会话、点「回到最新」和发送之后没有方向。
- **页面自身造成的位移不是输入。** `VirtualTimeline` 在渲染改动页面之前读取滚动位置：只有这时已经不同于上次所见的位置才算读者滚动。渲染之后才出现的差异（内容变短、浏览器自己的锚定）只更新记录，不触发翻页。
- **视野内的行只在读者到达边缘时让位。** 窗口已满时，一端加载一页，另一端就要让出一页的条目（`TIMELINE_PAGE_ITEMS`，与后端的 `PAGE_SIZE` 一致）。如果让出的条目包含视野内的行，这次加载不再提前（原来距边缘半屏就预取），而是等读者滚到边缘本身。此时沿途的内容都已经过视野，没有被跳过的正文。普通的长历史不受影响，仍然提前预取。
- **自动补页从读者所在的一端生长。** 向上时保留窗口首端，其余情况（贴底、向下、刚打开）保留末端：`mergeTimelinePage` 的 `retain` 由调用方给出，不再由翻页方向推出。补页会挤掉视野内的行时不补，等读者自己滚动。一次补页没有改变窗口，说明缓存已满，不再重复请求。
- **阅读位置是视野内的所有行，取其中仍在窗口里的第一行。** 顶部的行被裁掉后，由下一行接替并留在原位。没有可用记录时（输入刚清掉它，或读者刚滚动过），在渲染改动页面之前现取，这样补偿的正好是这次改动造成的位移。
- **折叠行和工具调用串在窗口移动时保留原来的 id**（`keepWorkIds`）：一组里只要还有上一次属于某一组的记录，它就是那一组。
- **任务收尾的刷新只换最新一页。** `keepPosition` 的刷新保留窗口里位于这一页之前的条目（`mergeTimelinePage` 的 `keepEarlier`）。窗口与这一页没有交集时照旧整体替换。
- **翻页请求在界面重绘之前不重复发出。** `useTimelineHistory.load` 用即时状态判断：请求在途、结果已到但还没显示、上一次失败并等待重试时，不再发前后翻页的请求。滚动事件可能先于重绘到达，只看渲染时的 `busy` / `error` 会对同一游标再请求一次，并把刚出现的错误提示冲掉。

## Alternatives considered

- **只改方向判断。** 能消除回弹，但提前预取照样会把视野内、读者还没读到的正文挤出缓存（用合成数据实测：在最新处向上滚 20 像素，视图直接跳到会话开头）。
- **按展示行而不是原始条目计上限，或遇到长工具组时临时放宽。** issue 要求保留现有上限。行数随折叠和展开变化，同一组数据展开后就是几百行；上限的用途是约束内存和渲染量，它们取决于条目。
- **由后端为每组过程记录提供稳定 id。** 需要改索引里已写入的行，也就是提升 `PROJECTION_VERSION`，所有会话的索引都要全量重建（见 ADR 0010）。前端沿用上一次的分组就能得到同样的稳定性。
- **窗口已满时一律不提前预取。** 普通的长历史翻过六页后窗口就一直是满的，这样每翻一页都要在边缘停一下。只有让位的条目落在视野内时才需要等。
- **缓存放不下时裁掉新取来的一页，保住视野内的行。** 视野不变，但读者停在那个位置时每个滚动事件都会发出一次白费的请求，仍然要先判断这次加载该不该发。

## Consequences

- 持续向下或向上滚动可以越过占满窗口的工具组，沿途每条消息都经过视野；没有反向输入时不再请求读者身后的页。
- 缓存放不下长工具组两侧的正文，所以越过它时视图会「翻页」：读者到达边缘后，身后的正文让出，折叠行留在原位或移到视野另一端，前方的正文接上。这是保留上限的代价。
- 在这种窗口里翻页不再提前预取，读者到达边缘后要等这一页返回。
- `TIMELINE_PAGE_ITEMS` 需要与后端的 `PAGE_SIZE` 保持一致。按字节的上限（`MAX_TIMELINE_BYTES`）造成的让位没有预判，这时由阅读位置的接替规则兜底。
- 一次滚到窗口顶端、同一帧内旧页就返回时，这一位置还没有渲染过，视图停在新窗口的顶端；隔一帧返回则保持原来的消息不动。
- `smoke:history` 增加了 #202 的合成数据（623 条，其中一轮 502 条过程记录）：两种窗口高度下的单向上滚和下滚（逐帧记录窗口首尾和视野内的消息）、主动换向、顶端继续上滚、任务收尾时停在更早一页。合并规则的用例在 `ui/tests/timeline-cache.test.mjs`，分组 id 的用例在 `ui/tests/uiux-regressions.smoke.mjs`。
