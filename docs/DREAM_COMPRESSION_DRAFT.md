# DreamAgent 会话压缩设计初稿 v0.1

状态：待真实 JSONL 样本验证。本文件描述实验方案，不修改现有记忆处理行为。

## 目标与范围

用纯程序减少 DreamAgent 读取的重复内容、协议包装和工具日志，同时保留用户表达、助手结论、操作顺序和证据引用。压缩不调用模型，不预设必须达到的压缩率。

本轮先验证压缩效果，不实现自动整理、长期记忆写入、人格提取或存量数据迁移。输入文件只读，实验不能修改真实会话或记忆数据库。

成功条件：能够解释每项删减；保留内容可定位原文；不能以“文件变小”代替信息质量验证。

## 数据路径

```text
原始 JSONL（只读）
  → 识别事件格式、校验、建立来源位置
  → 归一化、合并有可靠关联的流式事件
  → 通用 compact 视图
  → Dream 专用压缩视图
  → 独立的预算分块与输入渲染
```

现有 compact 同时供历史检索和记忆详情页使用。因此，实验先在内存生成两个视图，不覆盖生产 compact.json。通用视图负责来源关联与安全的结构整理；工具日志摘取等有损处理只作用于 Dream 视图。未来是否调整持久化 schema，依据实验另行决定。

## 1. 输入和来源定位

- 根据实际样本区分 Cleo 事件、provider 原生事件或其他 JSONL，不假设所有格式具有相同字段。
- 优先使用原始 event ID、seq、turn ID、item/message ID、tool call ID；缺少 ID 时用文件行号和 JSON 字段路径建立仅用于实验的定位。
- 原始 seq 应严格递增；没有 seq 时使用文件顺序，不用时间戳重新排序。
- 无法解析的行、无法识别的事件必须计入报告。不能静默跳过后声称完整处理。
- 不修改原始文件。给模型或输出到报告的正文沿用脱敏要求；被省略的原始正文只通过本地来源定位回溯。

## 2. 归一化和流式合并

第一版仅按已识别协议的确定规则合并，不做语义去重。

1. 同一消息的 delta 按协议顺序拼接；不能把两个相同 delta 当成重复，因为原文可能确实连续重复。
2. 同一 item 的累计快照使用协议指定的最新完整版本；不能把完整快照继续追加到 delta 后。
3. 完成事件已包含完整正文时，只消除能够确认被其覆盖的中间副本。
4. 调用与结果按可靠 ID 关联，保留开始和完成位置。关联不代表把后来的结果提前到调用位置展示。
5. 缺失结果、取消、失败、运行中状态分别保留；缺少最终事件不能推断成功。
6. ID 不足、快照与增量冲突、协议不明时不猜测合并，计入未解决关联统计。

同一次操作的关联记录共同保留来源 ID；不同次操作即使正文相同，也保留发生顺序和各自证据。

## 3. 按类型压缩

| 类型 | v0.1 规则 | 边界 |
| --- | --- | --- |
| 用户消息 | 脱敏后保留全文 | 不删重复强调、不识别所谓闲聊、不摘要；超长由分块处理 |
| 助手文字消息 | 保留全文，只去除已确认的流式副本 | 不用关键词猜测“最终结论”并删除中间回复 |
| 工具参数 | 保留工具名、命令、路径、查询、关键选项 | 大正文、补丁保留预览和来源定位，标记不完整 |
| 终端、测试输出 | 状态字段加有预算的原文片段 | 退出码 0 不等于测试通过；统计须有明确来源 |
| 文件读取、搜索结果 | 保留文件/URL/行号及正文片段 | 不一律省略；未知重要内容可能被遗漏，必须可补读 |
| 文件改动 | 保留路径、操作、状态和已有改动统计，附有限 diff 片段 | 不从文件名推断变更目的或效果 |
| 计划、权限、取消、错误 | 保留状态和相关文字 | 一次权限许可仅描述当次事件，不转成永久授权 |
| 图片、二进制 | 保留附件定位、类型及已有说明 | 不发送 base64；不把未查看图片推断成文字事实 |
| 已知协议噪声 | Dream 输入省略心跳、token 用量通知等 | 事件类型和数量仍进入实验清单 |
| 未知事件 | 有限原文预览、结构信息、来源定位 | 明确标记未知及省略，不能声称内容已完整理解 |

工具名称由已识别 provider 适配到操作类型。不能只依赖当前 read_file、grep 等少数名称，也不能通过名称包含某个词就认定全部语义。

## 4. 工具正文选取算法

初始实验使用固定字符阈值，便于复现且不依赖特定模型分词器。这些是内容选取参数，不是请求 token 上限。

| 参数 | 初始值 |
| --- | ---: |
| 普通工具记录的参数、状态和正文合计目标预算 | 6,000 Unicode 字符 |
| 失败/错误工具记录合计目标预算 | 12,000 Unicode 字符 |
| 其中开头预览上限 | 1,000 字符 |
| 其中结尾预览上限 | 2,000 字符 |
| 错误命中上下文 | 前后各 3 行，仍受总预算限制 |

选取步骤：

1. 短记录完整保留，不为凑压缩率删除内容。
2. 长记录先预留命令、路径、调用 ID、状态等字段所需空间。
3. 提取明确结构化结果；仅对已支持格式解析测试统计等信息，保留其原始字段或原文位置。
4. 为首尾预览保留空间，剩余空间选择错误、失败片段。按原文顺序选取，合并重叠区间；匹配太多时记录未展示数量。
5. 所有片段最后按原文顺序呈现，不产生模型式摘要。不使用“保留了全部错误”之类无法保证的描述。
6. 超长单行也适用总预算，必要时保留行内片段及偏移。
7. 关键字段本身已超预算时，保留关联信息并交给分块层拆分，不静默截断命令后当成完整命令。

JSON 使用同一个整条记录预算，不能让数组或嵌套对象绕过限制。对已知结构优先取状态和结果；对未知结构保留有限结构化预览、总项数和来源。深层或超预算子树用省略标记代替，避免输出无效 JSON。

## 5. 正文复用

第一版先消除协议确认的重复传输。其他重复正文只允许在同一个最终输入块内复用：

- 事件记录仍各自存在，例如“失败 A → 失败 A → 成功 B”保留三次执行。
- 后一次可引用本块已展示的相同正文；不通过相似度或脱敏后相等来证明原始正文相同。
- 块中必须存在被引用内容；跨块需要重新展示必要正文，不能使用模型无法解析的引用。
- 若引用及其映射比正文更长，则不复用。

正文复用是可单独启用的实验项。报告必须区分流式合并、正文复用和有损摘取的各自收益。

## 6. 证据与处理清单

每条保留记录关联原始事件及字段位置；原文片段记录字符区间，拆分后仍指向同一原始事件。额外记录所用压缩规则版本。

每个源事件在实验清单中标记为以下一种主状态，并可附加关联信息：完整保留、合并到已关联记录、引用已有正文、部分保留、按已知规则省略、未识别或解析失败。

“有来源 ID”不等于“模型看过整个事件”。证据验证应针对实际展示的片段；被截去的内容不能当成模型已读取的依据。需要补读时，由程序返回脱敏且有预算的源片段，不让模型全文重读原始日志。

## 7. 分块接口

压缩不承诺整个会话落入单次上下文。分块层优先沿回合、消息和工具操作边界切分，单条超长正文继续拆分。

初始成本实验按每块约 20k tokens 新内容，另计提示词、衔接信息和输出预算。实际请求上限须由目标模型分词或可靠计数控制；字符阈值不能替代 token 检查。

只有确定的消息/操作单元完成后才能提交处理进度；运行中操作或被拆成多段的事件不能因为读了前半段就标记全部完成。跨边界的未完成关联留待后续处理。

## 8. 收到 JSONL 后的实验方法

并排比较：

| 版本 | 用途 |
| --- | --- |
| A：原始 JSONL | 原始体积及事件构成 |
| B：现有 compact | 仅在该输入格式适用时运行；否则明确不适用 |
| C：仅归一化、流式合并 | 测量消除重复和协议包装的收益 |
| D：加入 Dream 内容摘取 | 测量有损压缩的增量收益 |
| E：最终分块输入 | 包含重复提示词、跨块衔接、引用映射及实际发送格式 |

报告同时给出：

- 原文件和各输出的 UTF-8 字节数、正文字符数；另用一致的紧凑序列化比较，避免把缩进变化误当成内容压缩。
- 若有目标模型的可靠 tokenizer，报告其输入 tokens 和 tokenizer 名称/版本。否则标记 token 估算，不能称为精确 Luna 或 GLM 用量。
- 保留率 = 压缩后大小 / 压缩前大小；节省率 = 1 - 保留率。明确是字节、字符还是 token 口径。
- 相对原始 JSONL 和相对现有 compact 的两组结果；单独列出剔除二进制、协议元数据后的正文变化。
- 用户文字、助手文字、各类工具、未知事件的大小和处理清单统计；不能只给总比例。
- E 的总输入 token 消耗，用于费用估算。D 的文件大小不能直接冒充总请求成本。
- 首次历史整理与后续增量整理分开测量；没有追加样本时，不宣称验证了增量节省。

人工核对用户要求、用户纠正、失败后恢复、取消/权限事件、最长工具输出和未知事件，并展示几组脱敏后的前后对照。用户和助手正文在脱敏后应能从保留片段还原；有损工具记录明确说明省略范围。来源覆盖率不代表语义完整率。

## 9. 实验产物与验收

输入 JSONL 原地只读。运行脚本、临时输出、日志等全部集中到操作系统临时目录下的单一任务目录；完成后清理。最终只保留约定的报告或样本，不向记忆数据库写入实验数据。

首轮通过条件：

1. 没有静默漏掉输入行或未识别事件。
2. 没有删除真实的用户重复表达或独立操作。
3. 消息及状态转换顺序正确；关联结果没有被提前呈现。
4. 已展示正文和引用均能回溯，正文复用不产生悬空引用。
5. 大 JSON、长单行、长回合不能绕过记录预算和最终请求预算。
6. 明确展示工具摘取造成的信息损失，不只展示节省率。

根据真实数据决定阈值调整及生产实现范围。本稿不加入语义相似度去重、额外模型摘要、自动认定最终决策等机制。
