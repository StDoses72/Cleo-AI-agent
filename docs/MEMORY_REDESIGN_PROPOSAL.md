# Cleo 记忆重构方案（待审查）

日期：2026-09-09。本文是设计提案，尚未修改生产代码、配置或用户记忆数据。

> 审查状态更新：下文的“JSON 作为正文权威源、Markdown 作为投影”不再作为推荐结论；是否加入独立语义判断也暂缓决定。该稿尚不能作为实施规格。后续项目对照、源码证据及收敛方向见 [记忆系统项目研究](D:/doses72Proj/Cleo-AI-agent/docs/MEMORY_SYSTEMS_RESEARCH.md)。persona 改造等附带建议同样未获确认。

## 1. 推荐决策

- `MEMORY.md` 只呈现用户偏好；项目版本可附一个按下“整理”时的状态快照。禁止事实列表、历史测试结果、代码结构、提交记录和逐块待办堆积。
- 停止自动提取和持久化原子事实。具体事实保留在已有事件历史中，需要时检索原文。
- 记忆领域使用小型 JSON 文件保存偏好、来源和单个快照，Markdown 是可读投影；不再使用事实记忆 SQLite，也不引入向量数据库。
- 暂时保留 `sessions.sqlite3` 作为会话目录的可重建索引。这不是事实记忆库。彻底移除它属于可单独审查的后续改造。
- 恢复语义判断，但使用用户已配置的远端模型，复用 API/订阅 runtime；不用本地 sentence-transformers，也不默认下载任何语义模型。
- 整理必须先完成跨块合并和证据复核，再整体发布。分块结果不是长期记忆。

## 2. 当前实现为什么会膨胀

`cleo/agents/dream.py` 仍要求提取 facts、decisions、constraints、corrections、actions、artifacts 等广泛类别。
`cleo/memory/consolidation.py` 把每个块的条目逐个 upsert，然后保留旧 Markdown 叙述，再渲染最多 100 条记忆。
`cleo/memory/store.py` 的内容指纹解决完全相同条目的重复写入，不能解决同义重复或旧状态被新结果替代。

因此，仅改变 Markdown 排版或把事实藏进 SQLite，不会解决分块误读和无限积累。
现有源码已移除旧本地语义 gate，`settings.py` 仅丢弃旧 `memory_gate` 配置；磁盘存在模型目录不代表当前源码仍加载它。

## 3. 明确区分三种信息

| 信息 | 保存位置 | 使用方式 |
| --- | --- | --- |
| 用户希望如何协作 | 小型偏好文件及 MEMORY.md 投影 | 会话启动时加载当前适用范围 |
| 上次整理时进行到哪一步 | 一个有来源、有时间的状态快照 | 用户续接工作时提供；不能当实时状态 |
| 具体发生过什么 | events.jsonl 及可重建检索投影 | 按问题检索，再读取原始证据 |

不再创建独立的自动事实库，不把它改名为知识卡片或换成 JSONL 后继续堆积。
任务文档、设计文档和用户主动维护的知识文件仍按普通项目文件使用。

## 4. MEMORY.md 内容契约

建议初始预算：项目文件总计不超过约 1,200 代理 tokens；偏好最多 20 条；状态最多 5 行、约 300 代理 tokens。
这是待验证的产品预算，不是已证明的最优值。超过预算应合并、缩短或提示容量冲突，不能静默删除用户明确保存的偏好。

示意格式（仅展示样式，不把示例视为已确认的新偏好）：

```markdown
# 用户偏好
- 在 Java 课程辅导中优先使用普通循环，避免未经解释的 lambda。
- 课程练习按小步骤推进，每一步解释后再继续。

## 上次整理时的状态
范围：17214 / hw1；来源：指定会话
截至：明确的事件时间；整理时间：明确的操作时间
已完成：最近一个已验证的里程碑。
待续：仍未完成且未被后续证据取消的一件事。
这是历史交接快照，当前文件和本次指令优先。
```

禁止追加 Facts、Decisions、Atomic Memory、Artifact References 等章节。
证据 ID、来源 hash、修订信息保存在机器元数据中，由 UI 展示，不把长证据串塞回 Markdown。
状态是唯一允许包含简短项目事实的例外，并且每次替换，不累积历史版本到正文。

## 5. 偏好的准入、范围与纠正

允许：语言、解释方式、代码表达风格、协作节奏、输出形式等明确影响后续互动的用户偏好。

不允许：某次工具被拒绝、环境缺少依赖、测试通过数量、代码实现细节、一次性任务要求、模型对用户性格的推测，以及从工具或网页里读来的指令。
“这一次不要改代码”应留在当前任务上下文；“以后辅导课程时都先解释再改”才可能成为该范围内的偏好。

默认只自动接受用户明确表达的稳定偏好。反复行为可提出候选，但不能仅凭观察自动升级为长期偏好；没有明确信号就不写。
证据可包含助手的提议及用户回应，但必须读足上下文，不能把孤立的“好”解释为接受全部提议。

偏好按稳定 ID 更新，不按整段正文生成新 ID。新结果只能提出 add、update、remove、no_change，update/remove 指向已有 ID。
同义表述合并；新明确纠正替换旧值；一次例外不改变长期值；仍有歧义时保持旧记录并展示待澄清候选。
用户明确删除的偏好需要保留最小的抑制标记，避免重跑旧历史后复活；新的明确“记住”可重新启用。

作用域默认收紧到 space + project，必要时附课程或子目录适用条件。17214 的 Java 偏好不能自动变成所有编程场景的偏好。
全局只接受明确全局偏好，不从项目观察自动提升。当前用户指令始终优先。

## 6. 状态快照的语义

“整理”开始时固定选定会话的事件上界。模型只能依据该上界之前的证据形成快照，操作过程中追加的消息留待下一次处理。
快照标记 source_thread、work_item、covered_until、整理时间和证据来源。

项目 MEMORY.md 最多显示最后一次手动整理所选工作项的快照。对于 17214，必须注明 Lab 1、Lab 2 或 HW1，不能合成为一个含糊的课程当前状态。
多个会话并行且结论不兼容时，不用最后写入者覆盖出一个虚假的全局结论；提示选择工作项或显示无法确定。
晚整理的旧会话不应仅凭整理时间覆盖同一工作项的较新状态；比较事件覆盖时间和来源，歧义时保留现有快照。

中途失败、后续成功，只呈现截至上界的最终有效状态。用户回退后，不能把曾经成功的实现写成仍然存在。
测试被启动但未见完成结果写“未验证”；历史成功不能证明当前文件仍通过。
新事件发生后，UI 标记“有更新，尚未整理”，不默默把旧快照称作当前状态。
没有足够证据时允许不生成快照，不强迫模型凑满五行。

## 7. 新整理流程

```text
固定原始历史快照
  → 现有结构归一化、脱敏和分块
  → 每块提取少量偏好候选与暂存的工作进展
  → 跨块合并：更新偏好，消除已完成/被取消的待办
  → 对最终拟发布内容做证据语义复核
  → 确定性校验与一致发布
  → 偏好 + 一个状态快照
```

保留当前可靠的事件来源、流式去重、正文复用、分块预算和断点恢复，不为此次重构重写整个事件采集层。
默认继续保留工具正文的结构压缩，不用本地模型预先删掉语义证据。

跨块暂存只服务本次整理，不成为永久事实集合。使用固定大小的工作状态，附短原文证据与可回读指针；新块可以完成、取消或纠正旧事项。
最终复核若发现缺少后续证据，按来源回读有限上下文，不仅检查改写后的摘要。

增量处理以已提交游标为起点。复用既有 API/订阅 runtime 的整理模型；复核使用独立上下文，可先使用同一配置模型，不要求新增服务或单独账号。
同一模型复核不是正确性保证，必须用实际案例验证。

最终偏好复核检查：是否真为用户偏好、是否有直接支持、范围是否扩大、是否为临时例外、是否重复或纠正已有条目。
最终状态复核检查：是否覆盖后续完成/取消/回退，是否混淆提议与接受，是否把读取当修改，是否把过去环境限制当现在能力。
模型输出明确的接受、拒绝、替换、无法确定及对应引用，不用相似度阈值判断真假。

程序校验 schema、来源位置、scope、目标 ID、预算与发布版本。模型失败或证据不足时不推进完成游标，旧有效版本仍可读取。
偏好数据和 Markdown 投影必须一致发布或能恢复到一致版本；不能一份新、一份旧却显示整理完成。
完成后清理中间块候选，只保留当前结果、必要来源和恢复游标。失败时保留可重试的 checkpoint，取消/丢弃时清理。

## 8. 无本地模型的历史语义检索

语义筛选分为两件事：写入时判定偏好是否成立，读取时判定哪些历史与问题相关。Embedding 相似度只能辅助后者，不能代替前者。

推荐第一版不使用 embedding：

1. 当前 agent 结合问题生成少量中英文关键词、同义词和代码标识符；这一步可利用已有推理过程。
2. 按明确项目、工作项、时间与会话范围做词法初筛，复用现有中文切分能力，必要时加入 BM25。
3. 将有限候选片段交给现有远端模型语义重排，只返回候选 ID 及相关性，不把重排解释存成长期事实。
4. 对选中片段及前后文调用 read_thread，回答带来源。

建议起始预算为候选 30–50 段、返回 5–8 段，并限制单次输入 tokens；数值由真实评测调整。
重排只能整理已召回的候选，不能找回从未入选的内容。低召回时扩大关键词或扫描会话标题与用户消息；明确返回 partial，不能将扫描不完整说成没有历史。
远端不可用时回退为注明模式的词法检索；偏好读取和历史读取继续可用，语义整理保留失败状态，不偷偷下载本地模型。

专用远端 rerank API 可作为后续性能优化；当同义改写仍系统性漏召回时，再评估远端 embedding。两者都不作为第一版依赖。
复用用户选择的 provider 处理脱敏后的必要片段；新增外部服务必须在配置中明确数据发送对象，不默认把全历史上传新厂商。

## 9. 存储与 persona

推荐逻辑结构：

```text
memory/
  user/memory.json                     # 显式全局偏好及其来源
  user/MEMORY.md                       # 只呈现全局偏好
  <space>/projects/<project>/
    memory.json                        # 当前项目偏好 + 至多一个状态快照
    MEMORY.md                          # 小型可读投影
    sessions/<session>/
      manifest.json                    # 已有元数据
      events.jsonl                     # 原始历史
      compact.json                     # 可重建检索投影
      dream.json                       # 增量游标/必要恢复状态
  sessions.sqlite3                    # 暂留会话目录索引
```

memory.json 只存偏好、一个快照及必要证据元数据，不允许 fact 数组或随历史无限增长的 block_results。
UI 编辑偏好更新规范数据并重新生成 Markdown；不维护两份可独立写入的真相。直接编辑 Markdown 的行为必须提示或提供显式导入，不能静默覆盖。
历史检索先扫描现有文件投影并复用缓存，不额外落一个大型事实数据库。未来性能确实不足时才设计可删除重建的检索索引。

建议停止 DreamAgent 自动生成 persona。沟通习惯中有明确用户证据的部分归入偏好；Cleo 的基础人格仍作为独立人工配置。
已有 PERSONA.md 的人工内容不删除、不重写；旧自动条目退出默认注入，逐条核对后才转成偏好。避免“偏好只剩十条，persona 又积累几百条”的旁路。

## 10. 读取与产品界面

- 启动时加载显式全局偏好和当前 scope 偏好，必要时附带对应工作项的状态快照。
- 续接其他工作项时按来源读会话，不能套用上一次整理的另一任务状态。
- 保留 list_threads、search_conversation_history、read_thread，并保持 Chat/Codex/Claude/ACP 使用同一读取层。
- 内置调用方更新后移除 search_long_term_memory；过渡期若保留兼容入口，只能返回偏好并明确结果类型，不回读旧事实库冒充有效新记忆。
- 记忆页呈现“用户偏好”“上次整理状态”“历史来源”，不再以提取事实条数评价整理成功。
- 整理完成报告新增/更新/移除的偏好和替换的快照；没有值得记忆的内容是正常成功结果。
- 手动整理刷新快照。自动路径默认只处理明确的记忆/偏好纠正，不在每次工具输出后生成永久知识；日常事件保存和索引照常运行。

## 11. 迁移步骤与边界

1. 先用 17214 做只读试跑：生成新偏好和单个快照的预览，和现有 67KB 文件逐项对照，展示排除原因。
2. 优先从原始用户消息重新确认偏好；旧 MEMORY.md、SQLite、persona 只能提供候选线索，不能直接视为用户事实或指令。
3. 核实旧生成内容是否存在用户手写且仅此一份的数据。发现独有内容必须列出并明确归宿，不因名为“派生数据”就删除。
4. 完成新读写、MCP、UI 与恢复验证后切换到新版本，移除旧事实的默认检索和注入路径。
5. 只有在确认无独有用户数据、引用迁移和原始历史完整后，才清理旧 memory.sqlite3、自动 persona 库及旧生成段；不把旧库改名永久当备份。
6. 移除本地语义模型相关依赖和产品下载入口；对磁盘残留模型先确认是 Cleo 专用、无其他任务引用，再按准确路径清理。不能递归删除公共模型缓存。
7. 不改 AGENTS.md，不自动创建/更新 skills；保留现有会话数据、真实仓库和共享依赖。

此次方案审查不执行上述迁移，也不承诺未验证的删除安全性。

## 12. 验收条件

- 17214 的新 MEMORY.md 无事实列表、无事件长串、无重复测试状态，符合预算；只含已确认适用的偏好与一个带工作项的快照。
- 同一来源重复整理不新增条目；一百次无偏好变化的会话不导致偏好条目数线性增长。
- “先失败后通过”“实现后回退”“只读不改”“临时不用 lambda”“取消待办”能得出正确最终结果。
- 明确的偏好纠正替换旧值；删除后重跑旧会话不复活；全局/项目/子任务不串用。
- 老会话晚整理、并发整理、处理中追加消息、模型失败、发布中断都不产生错误覆盖或虚假成功。
- 断网或无模型时仍可加载偏好和读取历史；不加载 torch、sentence-transformers 或下载权重。
- 中英文同义问法、代码符号、跨会话追问有人工标注案例；分别测候选召回、重排和最终回答，不只测相似度。
- 对比无长期偏好、纯词法历史、语义重排三种配置的准确率、误注入、延迟和 tokens；没有效果数据前不声称更准确或更便宜。
- 运行相关回归、全套测试、已配置检查与 diff 检查；试跑及测试临时文件统一放任务临时目录，完成后清理。

## 13. 参考依据与适用限度

- [Claude Code memory](https://code.claude.com/docs/en/memory)：短入口、按需读取、规则与自动记忆分开。其内容范围比本方案宽，不照搬其项目事实记忆。
- [Letta Memory & dreaming](https://docs.letta.com/configuration/memory)：后台整理、复核并更新既有记忆。借鉴更新与整理，避免简单追加分块产物。
- [LangGraph memory overview](https://docs.langchain.com/oss/python/concepts/memory)：会话状态与跨会话记忆分别设计，按 namespace 控制范围。它不要求所有对话内容都变成长期条目。
- [Voyage reranker](https://docs.voyageai.com/docs/reranker)：词法候选也能接语义 rerank，不必先建立向量数据库。专用 reranker 解决相关性，不能承担偏好真实性和状态纠错审核。
- [本仓库语义实验](DREAM_SEMANTIC_EVALUATION_V01.md)：结构压缩保留文字，不等于模型提取正确；已有案例支持加入跨块状态合并和有限原文复核。

以上来源支撑设计原则，不能证明这套 Cleo 提案已经有效；效果以第 12 节验收为准。
