# DreamAgent 压缩 v0.1：真实会话实验报告

## 结论

这份样本的主要膨胀来自终端输出流式事件及其重复包装。优先合并流式记录、复用确定相同的正文、移除已知用量通知，即可大幅减少 DreamAgent 输入，不必先截取工具正文。

- 保留工具正文的分块输入：252,064 个代理分词 tokens，比现有磁盘 compact 少 **92.735%**，分为 14 块。
- 开启工具正文摘取的分块输入：184,003 tokens，比现有 compact 少 **94.696%**，分为 10 块。
- 工具摘取额外节省 68,061 tokens，但部分省略了 46 条归一化记录。当前证据更支持先实现保留工具正文的版本。

这里的“保留工具正文”仍包括脱敏、去除重复传输和省略已知协议用量通知，不表示原始 JSONL 的逐字节无损压缩。

## 计量口径

全部 token 数使用同一个 `tiktoken 0.14.0 / o200k_base` 分词器，以便横向比较。没有验证它与 Astra、Luna 或 GLM 的服务端分词完全一致，因此它是**代理分词计数，不是精确 API 账单**。

字节数按被比较文本的 UTF-8 编码计算。内存重建版本使用 LF；磁盘文件可能使用 CRLF，因此单列磁盘版本和紧凑序列化版本。字符数按 Unicode 字符计数。

节省率 = 1 - 新版本大小 / 基准大小。正文保留率与事件覆盖率是不同指标，不能互相替代。

## 膨胀来源

- 12,063 条 `item/commandExecution/outputDelta`，占全部事件的 **94.55%**。
- 这些 delta 属于 66 个有可靠关联 ID 的工具操作。
- 保持事件顺序、不跨其他事件合并后，12,063 条 delta 归并为 113 段连续输出，减少 11,950 条重复包装记录。
- 66 个最终工具结果中的 aggregatedOutput 与关联 delta 的顺序拼接结果完全一致。实验将最终重复正文替换为对已保留输出的引用，避免重复发送 371,890 个字符。
- 另外消除 105 处 content 与 payload 中确认相同的副本。
- 全部事件归一化为 808 条记录；Dream 阶段另省略 124 条已知 token 用量通知。

原始事件紧凑序列化中，terminal_output 类型合计 7,202,715 字符；归一化后降为 413,093 字符。此处主要节省的是大量短片段各自携带的元数据及重复字段。

文件改动记录仍较大：归一化后 534,704 字符，摘取后 354,334 字符。不同次修改的记录和状态仍保留，不把“最后一次状态”当成整个历史。

## 有损摘取的实际影响

默认工具记录正文目标预算为普通 6,000 字符、失败 12,000 字符；选取结构化状态、原文首尾、错误匹配及邻近行，使用整条正文预算限制嵌套 JSON。关联元数据及输入包装另计。

- 13 条合并后的终端输出记录被部分保留。
- 33 条文件改动记录被部分保留。
- 用户消息、助手回复、存储为 thought 的 commentary、权限记录、取消等保护类别的正文不进行摘取。
- 关键命令字段自身过长时保留并交给分块，不能为满足目标字符数静默截断。

按源事件归属统计：638 条标为完整保留，2,144 条标为合并，9,852 条归属到部分保留的记录，124 条为已知用量通知。9,852 是被摘取的合并记录所关联的源事件数，不代表这些源事件的正文全部被删除。

仅比较归一化正文与 Dream 正文，代理 tokens 从 337,161 降为 220,947。这里同时包含协议用量正文的省略和工具摘取，所以不能把全部下降归因于日志摘要。

## 验证

真实样本自动验证通过：

- 输入 ID、seq 与顺序校验；12,758 条源事件均有处理归属。
- 证据映射每条源事件恰好归属一次；合并记录不跨中间事件移动结果。
- 33 条用户消息、28 条助手最终回复的脱敏后正文完整保留。
- 34 条 commentary 和权限、取消等保护内容在最终分块渲染后不变。
- 全部展示片段的字段路径、区间与归一化正文匹配。
- 默认版本检查 166 处引用；保留工具正文版本检查 168 处引用，均可在所在块内解析。
- 每条待发送记录恰好发送一次，正文引用不会抹掉独立事件。
- 原始 events.jsonl 在实验前后 SHA-256 一致。

10 个合成边界测试全部通过：

1. 连续相同 delta 必须拼接而非误去重。
2. 最终快照与 delta 不一致时保留两者。
3. 中间用户消息阻止跨事件移动输出。
4. 重复用户表达、失败后成功、取消状态仍保留。
5. 超大 JSON 和超长单行受正文预算限制，片段可验证。
6. 超长用户消息分块后可完整重建。
7. 跨块工具输出引用补入，不产生悬空引用。
8. 脱敏后相同、原文不同的内容不能错误去重。
9. 超长关键命令保留，交给分块处理。
10. 权限、未知事件均被记录，只有已知通知按规则省略。

## 限制与下一步

这是针对本次 Cleo/Codex JSONL 的临时实现，不是已经集成的生产压缩器。其他 provider 格式、实时追加和断点恢复没有经过真实样本验证；样本只测首次全量处理。

程序验证了结构、来源、精确重复和保护正文的保留，没有让模型提取记忆，也没有人工阅读会话来验证语义。因此尚未证明摘取后的工具正文足以提取全部重要记忆。

块内正文复用会要求未来提取器正确解析短引用；跨块对话衔接与最终候选合并还需单独验证。字符摘取阈值、代理 token 分块不能直接替代服务端真实 token 限制。

建议下一版优先实现：可靠流式合并、重复字段消除、块内精确正文复用及分块。保留工具正文作为默认策略；待记忆提取质量对照完成，再决定是否启用有损工具摘取。
