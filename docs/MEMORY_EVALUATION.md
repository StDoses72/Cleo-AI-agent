## 开发过程中实际遇到的失败

第一次完整开发集运行中，P06 的第一次调用返回了 JSON schema 本身，未返回符合 schema 的实例。生产校验拒绝该结果，没有修改原记忆；该案例第二轮因此未执行。这一失败没有隐藏为 mock 成功。

随后明确要求返回 JSON 实例并加入空编辑示例，再执行完整 3 次开发集和保留集，最终运行没有重现该格式错误。结构化输出仍可能失败；生产代码保留失败状态供重试，而非静默忽略错误字段。

确定性测试还发现了 Windows 换行差异：读写统一换行会影响未修改正文的字节保持。实现改为保留文件换行，并增加 CRLF 精确回归；对应 fixture 使用明确换行避免把测试文件写入转换当成业务变化。

首次 GitHub 平台检查还发现 `pytest` 控制台入口没有把源码根目录加入导入路径，导致
迁移测试无法导入 scripts。测试改为按明确文件位置加载迁移脚本，并使用与 CI 相同的
控制台入口复验；这与模型语义结果无关。
