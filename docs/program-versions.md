# Cleo 程序版本与恢复

[English](program-versions.en.md)

本文说明桌面版如何保留、切换和恢复程序版本。Cleo 曾经提供「本地进化」（让 Cleo 修改自身源码、构建并保存本地版本），
该功能已移除，原因与兼容保证见 [ADR 0009](adr/0009-remove-local-evolution.md)。下面描述的版本切换、可见重启、
自动回退和独立恢复入口原本与它共用，现在继续服务于正式版本更新。

## 更新与切换

1. 在「设置 → 更新」检查正式版本。安装版每六小时自动检查一次；下载和安装都需要用户操作。
2. 「其他版本」可以选择历史版本或预发布版本。清单与安装包按平台、版本、长度和 SHA-256 校验后才可使用。
3. 「重启并安装」把已校验的程序交给重启控制器：原程序退出，控制器备份数据、切换程序并等待新程序确认启动。
4. 启动失败时自动回到上一个程序，仍失败则回到保底程序；全部失败时恢复窗口保持打开，由用户选择。

下载完成不会在下次启动时自行安装。手动运行新版安装包后，首次启动会通过同一套可回退流程切换到新安装的程序；
如果当前使用的是旧版本保存的本地版本，或状态中仍有旧版本留下的未完成本地修改，则不会自动接管。

## 数据与恢复

所有程序使用同一 CLEO_HOME 和 Electron userData。切换版本只改程序，不覆盖用户数据。
切换前的备份是意外损坏时的留存副本，不提供随版本还原数据的选项；旧事务中的 restore 字段被忽略。

控制目录位于 Electron userData/evolution。目录名是磁盘格式的一部分，所有保留的程序（包括更早的版本）都读写它，因此不随功能改名：

- builds：保底程序、当前程序、已下载的正式版本，以及旧版本保存的本地版本。
- backups：切换前的自动数据备份，最多保留 3 份完整快照。
- downloads：已校验的安装包缓存。
- handoffs：重启控制器就绪握手。
- state.json：程序选择、构建登记、切换事务、清理队列与启动器刷新记录。
- releases.json：最近一次读取的正式版本列表。

旧版本可能还在这里留下 source、source-history-*、source-recovery-*、tools、acceptance、validation.json、
protected.json、release-jobs 等内容。当前程序不再读取或写入它们，也不会删除；正式版本切换时仍按原有事务把
source 归档为 source-history-*，切换失败时原样恢复。

首次安装更新或在应用内打开版本恢复时，Cleo 会把当前可用程序保存为保底程序；Windows 同时在桌面创建
「Cleo 恢复」快捷方式（Alpha 渠道为「Cleo Alpha 恢复」），以 `--cleo-recovery` 启动。保底入口不依赖主界面或
Python 服务，可以在主程序无法启动时使用。程序副本在 Windows 上通过原生文件复制、其他平台通过 original-fs 复制，
避免把 app.asar 错误地展开成虚拟目录。保底程序不自动清理。

## 版本保留与清理

通常只保留保底程序、当前程序和刚下载的正式版本；同一程序兼任多个角色时只存一份。状态中由旧版本记录的引用
（最近保存的本地版本、迭代起点、工作区基础版本、候选构建）继续受保护，回到那些版本时仍然可用。

切换期间暂时保留旧程序，直到新程序报告启动成功。Windows 占用或路径异常导致的删除失败会进入队列，
下次启动或操作重试。程序清理仅针对控制目录 builds 下的程序，识别并回收未登记的 UUID 构建残留；
不删除用户数据、源码归档或工具缓存。

自动数据备份限制为 3 份：当前切换事务和最近一次切换引用的备份优先保留，并计入限额，其余按 snapshot.json 中的
创建时间保留最新副本。新备份完整写入并记录到事务后、以及正常启动确认后，会清理多余的旧备份；历史积累的完整备份
也适用。复制期间可能临时多出一份，删除失败会记录并在下次重试。只清理 backups 下由 Cleo 创建的完整 apply-UUID
快照；无关目录、链接及无法确认完整性的备份保持不动。清理不会改写当前 CLEO_HOME 中的会话、配置或记忆。

在线运行环境在新版主界面和后端确认启动成功后，仅保留当前版本实际使用的一份。
同一在线运行环境目录下，旧版本和同版本的其他完整环境都会自动回收，即使旧安装位置仍登记引用；
旧版本或自定义安装再次启动时可能需要重新安装对应依赖，不能再依赖其在线环境永久保留。
尚未启用的更新版本、安装中的环境，以及可执行文件仍被占用的环境暂时保留；失败的删除会记录并在
后续正常启动或手动空间清理时重试。未确认健康、当前环境不完整、版本无法识别或路径为链接时不做此项回收。

每次以在线运行环境启动时，程序会在该环境根目录的 `installations.json` 里登记"哪个安装位置用了哪个
运行环境 key / 版本"；同一安装位置切换到新 key（原地升级）时，离开的旧 key 与离开时间保留在该条目的
`history` 里，直到旧环境目录被删除，所以登记不会覆盖"此安装已离开旧环境"的证据。空间清单据此给每套在线运行环境标注归属：`in-use`（当前程序、登记的构建、已安装
启动入口、另一渠道、依赖快照或启动登记仍指向它）、`retired`（已被健康的新版本取代，或登记使用它的安装
全部已切换到其他运行环境 / 已不存在，且没有其他引用）、`unknown`（完整但无人能证明在用，继续保留）。
条目带 `owners`（引用者及证据类型）与 `evidence`（退役依据）。登记文件缺失、损坏或指向其他 key 都不构成
删除授权；按登记判定的退役回收与按版本的回收共用同一组健康/事务/安装/下载门槛。

## 程序包

Release manifest 的 `evolution_protocol: 2` 表示程序切换保留当前数据，联网程序包为 `3`；
不接受更旧协议的发行包。字段名沿用旧称，是因为已发布的程序按这个名字读取它。启动不会自动下载或覆盖所选程序。

v0.12.2 及更早的程序包在 app.asar 旁附带 `evolution-source.tar.gz`；新的程序包不再附带，两种都能被识别和切换。

## 窗口启动与退出

面向用户的主界面、版本切换控制器和恢复界面统一由 `ui/electron/program-launch.mjs` 启动。
这些进程不设置 windowsHide，否则 Windows 会隐藏恢复进程的第一个原生对话框，
留下一个等待用户操作却看不见窗口的进程。后台 Python 和安装工具继续静默启动。

独立恢复窗口的取消或关闭会结束恢复进程；正常关闭主窗口会先结束后端再退出应用。
切换由当前程序创建独立重启窗口；旧程序收到窗口已显示的握手后才退出。
控制器等待主界面与后端就绪的确认，不能仅凭进程创建成功关闭进度窗口。
启动失败会先停止失败程序，再尝试上一个程序及保底程序，数据始终保留。
所有尝试失败后进度窗口转为持续可见的恢复入口，取消版本选择也不会自动退出该窗口。
应用内打开恢复选择时保留原窗口，确认版本后再开始受控重启。

## 与旧版本的兼容

- 旧版本（v0.12.2 及更早）仍可作为保留的程序被选中和运行，它们的本地进化功能在那些版本里继续可用。
- 状态中有旧版本留下的未完成本地修改（迭代、未保存的候选构建）时，当前程序拒绝正式版本切换，
  并提示从恢复入口回到那个版本保存或放弃；当前程序不会替用户归档或清理这些内容。
- 旧版本保存的本地版本可以从恢复入口选择。
- `cleo-evolution` 项目下的历史任务仍作为普通开发任务加载，目录为原来的源码工作区。
- 版本切换本身不执行数据降级或格式转换；存储格式的兼容要求不变：保留字段名、类型、语义、ID 和未知字段。
