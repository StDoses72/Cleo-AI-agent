# DreamAgent 响应解析器设计稿 v0.1

状态：待审阅，仅设计；不修改当前运行代码、模型配置或记忆数据。

## 目标

在模型响应与 Pydantic 之间增加确定性的解析、规范化步骤，让可明确识别的格式偏差不再直接导致整块失败。继续保留数据结构、来源作用域和证据有效性检查。

同时将摘要的目标长度与可接受上限分开：目标 2,000 字符，预算允许时接受至多 3,000 字符。解析器不改写记忆含义、不判断事实真假，也不增加自动语义复核模型。

## 问题依据

本次排查观察到三类问题：

| 现象 | 已确认的事实 | 本设计处理方式 |
| --- | --- | --- |
| 顶层多出 confidence、importance | 当前版本已对包含记忆集合的结果做定向兼容 | 统一收进解析器，保留条目自身的评分 |
| 摘要超出 2,000 字符，并新增摘要引用字段 | 一次只读复现得到 2,154 字符摘要和 summary_evidences；另一次未通过当前 JSON 解析 | 合法 JSON 中的已知辅助字段可规范化；摘要增加浮动空间；无法可靠解析的响应仍拒绝 |
| Luna 返回 E9748，被判 unknown evidence refs | 原始事件 9748 属于第 12 块的合并记录 E9742，覆盖 9742–9752 | 根据实际来源映射解析别名，而非只做字符串集合匹配 |

E9748 对应的原始事件存在，不代表当时的记忆结论一定受它支持。失败响应没有完整留存，本设计只解决可确定的引用定位，不将此次排查当作语义正确性证明。

模型选择必须按 `dream_model` 覆盖连接默认模型的规则确定。此次 Luna 运行所在连接的默认模型是 Astra，不能据默认值把实际整理模型认定为 Astra。

## 处理流程

```text
模型返回正文及结束原因
  → 保留当前未完成块的响应
  → 移除明确的文本包装
  → 严格解析 JSON
  → 规范化已知辅助字段
  → 按当前块的真实来源映射解析引用
  → Pydantic 校验规范化后的条目
  → 摘要长度与后续请求预算检查
  → 保存可继续的块结果
  → 沿用现有全部块完成后的幂等发布
```

原始响应与规范化结果分别保存，解析器不得原地改写原始正文。只有完整验证通过的结果可以推进块进度；“已经收到响应”不等于“该块完成”。

## 一、JSON 与包装解析

### 可直接规范化

- JSON 前后的空白及开头的 UTF-8 BOM。
- 整个响应由唯一一个 Markdown 代码围栏包裹，围栏语言为空或 `json`（大小写均可），围栏外没有其他非空正文。
- LF 与 CRLF 的围栏换行差异。JSON 字符串内部的换行、反斜杠和内容不做额外替换。

### 必须保留错误

- 多个 JSON 对象、多个代码块，或者 JSON 前后另有解释性正文。
- 非法引号、非法转义、缺括号、尾部截断、非标准 JSON 数值。
- 重复 JSON 键：不能用“后一个覆盖前一个”静默丢掉记忆集合。
- 顶层不是对象，或者只有评分等辅助字段，没有可识别的提取结构。

v0.1 不使用正则寻找“第一个大括号到最后一个大括号”，不自动补引号、补括号、执行表达式或把近似 JSON 当作代码求值。模型返回 `length` 等不完整结束状态时，即使尾部看起来能解析，也不直接标记完成。

## 二、字段规范化

规范化后的主结构仍为：

```json
{
  "memories": [],
  "persona": [],
  "summary": "用于下一块的摘要"
}
```

已知兼容规则限定如下：

| 输入字段或情况 | 规范化规则 |
| --- | --- |
| 顶层 confidence、importance | 作为未使用的批次元数据移出主结构并记录；不得填充或覆盖单条记忆的评分 |
| 顶层 summary_evidence_refs、summary_evidences | 若为字符串列表，作为可选摘要来源信息单独解析；不送进原来不接受这些字段的主结构 |
| 两种摘要来源字段同时出现 | 合并、去重，不选一个覆盖另一个 |
| 已知摘要来源字段类型错误或引用不可用 | 记录辅助信息警告，放弃不可验证的辅助引用；不能将其作为记忆证据 |
| 其他未知字段 | 保留原始响应并报告位置；v0.1 不全局启用 extra=ignore |

只有响应包含 `memories` 或 `persona` 集合时，才能移除批次元数据。仅返回 `{"confidence":1,"importance":5}` 不能被清洗成一个有效空结果。

单条记忆与 persona 的必要字段、类别、评分范围、数量上限和内容类型继续严格校验。缺少主体、缺少正文、非字符串列表等情况，不靠猜测补齐；辅助摘要引用也不能补作某条记忆缺失的证据。

## 三、证据引用解析

### 使用由程序生成的映射

映射绑定当前 space、project、session、固定源 hash、投影版本和当前块，包含：

- 当前块已提供的规范引用与来源 event IDs。
- 源快照中 seq 与不可变 event ID 的对应关系。
- 每个来源 event ID 归属的投影记录及其是否完整展示。
- 分段记录的精确 fragment ref；不能把整条记录的范围当作片段的精确范围。

当前 `Block.evidence` 不足以独立完成上述判断。实现时须从源快照和投影过程中生成这份映射，不能根据模型输出反向猜来源。

### 解析顺序

1. 优先精确匹配当前块已有的规范引用，保持其原有含义。
2. 未匹配时，仅对 `E<正整数seq>` 尝试原始事件别名解析。
3. 必须在固定快照中找到该 seq 对应的实际 event ID。
4. 该 event ID 必须属于当前块中完整展示的一条投影记录，且对应关系唯一。
5. 满足条件则返回规范引用、确切来源 event IDs 和转换记录，否则返回明确的引用错误。

以已排查的例子说明：

```text
模型引用 E9748
  → 固定快照中的真实事件 seq=9748
  → 此 event ID 归属投影记录 E9742
  → E9742 在当前第12块完整展示
  → 允许规范化定位到 E9742，并记录原引用 E9748
```

不能只判断 `9742 ≤ 9748 ≤ 9752` 就放行；范围可能包含被省略的事件或其他来源，必须查询确切成员映射。

### 不自动扩张证据

规范引用用于定位，实际写入的证据 event IDs 另行保留：

- 模型直接引用合并记录 E9742，沿用该规范引用原有的来源集合。
- 模型引用原始事件别名 E9748，只保留经过解析的原始事件 ID；不能因为改名就自动把整个合并组都视为模型引用过的证据。
- 多个引用最终对应同一来源时去重，但转换记录仍保留。

发布层必须消费程序解析出的证据集合，而不是再次只按规范引用展开所有 event IDs。该集合不能由模型提供，也不能在读取 checkpoint 时跳过来源重新校验。

### 仍然拒绝的情况

- 事件不存在、来自其他会话或只出现在其他块。
- 一个输入可以对应多个目标。
- 当前块只展示记录的一部分，无法确定原始事件的内容是否处于该片段内。
- 只相差一个数字、大小写类似等需要模糊猜测的引用。

v0.1 对分段记录继续要求精确 fragment ref。即使当前块恰好只有一个片段，也不能因此把任意原始事件别名映射过去。明确的格式定位不等于对记忆结论做语义背书。

## 四、摘要长度的浮动空间

| 参数 | v0.1 初始值 | 含义 |
| --- | ---: | --- |
| 目标长度 | 2,000 字符 | 在提示词中要求模型尽量遵守 |
| 容忍上限 | 3,000 字符 | 超出目标但未超过此值，不仅因长度而报错 |
| 单块事件预算 | 沿用 20k 代理tokens及64,000字节上限 | 不为塞入摘要而删除工具正文 |
| 整体输入上限 | 沿用90,000 UTF-8字节 | 包括可见指令、上下文、摘要和实际事件块 |

字符数按后端规范化后字符串的 Unicode 码点计数，与 Python/Pydantic 保持一致，不用 token 数或前端 UTF-16 长度代替。实际请求再单独统计序列化后的 UTF-8 字节；引号、换行和转义也占空间。

接受条件：

```text
摘要字符数 ≤ 3,000
且携带该摘要的下一次完整请求不超过现有输入预算
```

因此，2,154 字符摘要在预算充足时应正常接受。超过2,000字符仅记录“已使用浮动空间”，不弹失败提示。

预算检查必须使用实际拼装结果，不能用 `90,000 - block字节数` 简单代替；系统提示、schema、既有记忆、persona和其他上下文字段均需计入。后续请求上下文变化时重新检查。没有下一块时，不虚构下一块预算，但保留3,000字符的摘要上限。

代理分词和可见消息预算不能覆盖所有 runtime 隐藏指令；不把上述检查描述为任何模型都绝不会触及上下文限制。

### 超出上限时

- 不直接截断摘要，不删工具正文，不把失败改成空摘要继续。
- 保存本块原始响应及已经验证过的候选，单独标记摘要问题；不推进完成游标。
- v0.1 默认不增加自动模型修补调用。重试或解析策略更新时可以复用已保存响应，不应无提示地反复重做整个块。
- 如果需要自动处理超限摘要，可在后续版本设计“只重新生成摘要”的独立操作；它不属于本稿默认范围，也不能声称缩短后语义必然不变。

这意味着v0.1仍可能因超过3,000字符或真实预算不足而停下，但会保留可恢复结果，而非掩盖损失或无限重试。

## 五、解析结果与恢复状态

解析结果包含四部分：规范化后的提取数据、逐条解析出的证据集合、规范化记录、结构化错误。是否可以继续，由主数据、必要证据和摘要预算共同决定；辅助元数据警告不单独阻塞。

建议区分：

| 结果 | 行为 |
| --- | --- |
| ready | 保存块结果，继续后续块 |
| ready_with_notes | 存在确定的兼容转换，记录后正常继续 |
| blocked_json | 正文不能可靠解析，保留响应和解析位置 |
| blocked_structure | 主数据不完整或含未知结构，保留字段路径 |
| blocked_evidence | 必要引用不存在、越界或有歧义，不能发布本块 |
| blocked_summary | 条目已验证，但摘要长度或预算不允许继续 |

这些是恢复状态的原因分类，不必在界面增加六种新的顶层状态。现有“整理失败”可以展示准确原因，并保留已经完成的块数。

当前未完成块的原始模型正文应在校验前保存到现有恢复状态所管理的位置，不保存隐藏推理内容。只保留当前待处理响应，不积累每次尝试的历史副本。建议正文缓存上限256 KiB；响应超过上限时记录长度、摘要哈希和错误，不把截断正文当作可解析响应。

缓存绑定源快照、块摘要、解析器版本及实际模型选择。重试优先重新解析已保存正文；相同规则仍无法处理时，明确保持阻塞，不假装已经进行了新的模型请求。成功后清除当前原始响应，保留必要的规范化记录；明确放弃本次整理时一并清除其恢复正文。

模型名称记录解析后的有效选择，即 `dream_model` 优先于连接默认值。缓存升级或来源变化不得将旧响应套用到另一块；现有已完成块继续复用。

## 六、错误呈现

面向用户给出原因、位置和已保存进度，避免只展示整段 Pydantic traceback：

```text
已完成11/19块。第12块有一个引用无法唯一定位，当前响应已保留。
```

E9748满足映射条件时不应产生这条失败提示，而应在诊断记录中显示：

```text
第12块：原始事件引用 E9748 已定位到合并记录 E9742。
```

摘要浮动正常接受时仅记诊断，例如“2,154/3,000字符”；超过上限时明确说明是摘要问题，不能让用户误以为全部记忆或来源数据损坏。

## 七、实现范围建议

- 新增一个专门的响应解析模块，供API和订阅runtime共用，替代散落在 `_extract` 中的兼容分支。
- 在投影/分块层生成可靠的别名及完整展示信息，作为解析器的只读上下文。
- 保持Pydantic作为规范化主数据的校验器；摘要目标值与可接受上限分别定义。
- 更新checkpoint以保留当前阻塞响应和解析原因，发布时使用重新验证过的确切来源集合。
- 不改原始events.jsonl，不放宽跨项目/跨会话范围，不加入自动语义审核、模糊证据匹配或批量修改历史记忆。

## 八、验收标准

1. 普通JSON、唯一代码围栏、BOM及CRLF包装得到等价结果；记忆正文不被改写。
2. 多对象、解释性前后文、重复键、非法转义和截断响应仍被拒绝。
3. 顶层评分不会覆盖条目评分；只有评分的响应不能变成有效空结果。
4. 两种已知摘要来源字段可识别；辅助引用不能替代条目的必要证据。
5. E9748通过实际映射定位到当前块的E9742，并保留原始事件证据；映射不扩大证据集合。
6. 不存在、跨块、歧义及无法确认可见范围的片段别名仍被拒绝。
7. 分别验证1,999、2,000、2,001、2,154、3,000、3,001字符，以及中文、emoji、转义后字节预算边界。
8. 摘要超限不丢失已提取候选；重解析不重复调用模型，也不重复发布记忆。
9. 阻塞响应与旧块hash不匹配时不能复用；已完成块不因解析器升级而无条件重做。
10. 记录有效模型名称，覆盖“连接默认Astra、DreamAgent实际选择Luna”的情况。
11. 真实只读样本验证结束后清理实验临时目录，保持用户原始来源、配置与进度不变。
