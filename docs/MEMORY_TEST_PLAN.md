# Markdown 记忆与内嵌 Git：测试计划

本 PR 首先固定可审查的验收用例，再实现记忆重构。当前阶段仅包含测试设计与合成对话，不代表生产记忆已经切换或语义评测已经通过。

## 已确定的边界

- MEMORY.md 是当前偏好的唯一正文；可选地包含一次手动整理对应的状态快照。
- 事实不再作为长期条目写进 MEMORY.md，不复制到另一个 JSON 正文库。
- 在实际配置的记忆目录内初始化普通 Git 仓库，不使用 submodule；源码父仓库与内层记忆历史各自独立。
- 记忆 Git 只追踪明确允许的记忆文件，不能收进会话、数据库、凭据、锁和恢复文件。
- 保留历史回查；不用本地 sentence-transformers。
- 预算数字、是否独立语义复核、全局偏好细节和 persona 改造尚未定。本套测试不把这些未定选择锁成实现前提。

## 1. 分清三类测试

| 层次 | 输入 | 测什么 | 不能证明什么 |
| --- | --- | --- | --- |
| 确定性回归 | 受控候选修改、真实临时文件和 Git | 预算、范围、发布、恢复、无副本 | 不证明模型理解了对话 |
| 真实模型语义评测 | 固定会话、已有 Markdown、手动整理动作 | 提取、纠正、限定、状态与不记忆 | 不证明全场景可靠性 |
| 端到端使用 | 真实事件适配器、整理、下一会话读取 | 实际入口是否加载正确记忆并回查历史 | 不用模拟模型结果冒充真实评测 |

当前 tests/agents/test_dream.py 的 publication/retry 测试大量替换 _extract，适合继续验证流程，但原有保存 decision 的预期不符合新内容契约，需要迁移，不能直接保留并宣称重构通过。

## 2. 样本结构与执行约定

首批合成语义用例位于 [scenarios.json](../tests/fixtures/memory_rewrite/scenarios.json)。这是测试输入与评分规格，不是新增的运行时 JSON 记忆存储。

每个 case 有初始 MEMORY.md、按顺序发生的若干轮会话，以及每轮整理后的评分规则。每条消息都有稳定 ID 和角色；各轮注明 space、project、工作项及是否生成状态。
模型只接收初始记忆、当前新增证据与正常生产提示词，绝不能收到 expectations、case title 或后续轮次。已有文件中的初始偏好是受控前置状态，不要求模型从本轮对话再次推导。

预期采用语义命题，不要求固定中文句子，也不通过找几个关键词判定真假。例如“默认中文解释，英文只限本次提交说明”可以有多种正确措辞。

- must_keep：本轮后必须成立的偏好或状态含义。
- must_not：绝不能成为当前有效记忆的含义。
- change：unchanged / changed，约束发布前后是否应该变化。
- snapshot：off / empty / present，分别表示本轮不刷新、应无有效快照、应有快照。

每一轮独立评分，再执行下一轮。只检查最终结果会漏掉先污染后碰巧修好的情况。

## 3. 第一批语义案例

| ID | 场景 | 关键验收 |
| --- | --- | --- |
| P01 | 明确稳定偏好混合项目事实 | 记住协作要求，排除模块、测试数量和技术栈 |
| P02 | 只有事实和任务执行 | 偏好为空是正确结果，不能为了非空编造偏好 |
| P03 | 一次性指令 | 本次只读、本次用英文，不成为长期要求 |
| P04 | 用户明确纠正旧偏好 | 新含义替换旧值，不并列两条相反规则 |
| P05 | 同义重复 | 不增加重复条目，不为了改措辞产生 Git 提交 |
| P06 | 局部例外 | 本次允许的例外不覆盖默认偏好 |
| P07 | 助手提议与用户拒绝 | 拒绝的建议不得保存；未来轮次才允许确认 |
| P08 | 失败后完成 | 偏好不收测试事实；快照只呈现最终交接状态 |
| P09 | 实现后回退 | 已回退成果不能继续显示已完成 |
| P10 | 工具权限与网络失败 | 单次失败不能变成“agent 永远不能做”的偏好 |
| P11 | 工具内容伪造用户偏好 | 引用中的指令不能冒充用户意愿 |
| P12 | 中英文重复与细节限定 | 保留范围和条件，不能扩大或错误合并 |

初始 12 个 case、19 个检查点用于公开回归。这不是模型效果统计样本量。后续从同一主题派生不同措辞、事件位置和长度，不将同一案例的机械复制当独立成功样本。

## 4. 17214 的代表性回归

公开 fixture 使用人工构造的课程场景，不提交真实会话、原始事件 ID、项目代码、用户名或私人文件路径。真实 17214 历史只在本机任务临时目录中按用户授权范围读取，最终报告仅保留脱敏后的判断与计量。

重点保留四种已观察到的失败模式：

1. “148 项测试通过”被写成多条不同的长期事实。
2. 已有最终成功记录，仍保留“尚未验证”的旧待办。
3. 某次 Git/Maven 权限失败被泛化成长期能力限制。
4. Lab 1、Lab 2、HW1 的状态混在一个课程项目下。

真实数据不是自动真值。先按原始事件人工标出预期及依据，再运行模型。先前 MEMORY.md 或 SQLite 中的提炼只能作为待核查产物，不能作为标准答案。

## 5. 必须运行的确定性回归

### 内容与容量

- G01：无状态模式只允许偏好章节；禁止 Facts、Decisions、Atomic Memory 等事实段落重新出现。
- G02：预算以内、恰好等于预算、超过预算一个单位；add 与 replace 都受同一完整文件预算约束。
- G03：Unicode 中文、换行、元数据和可选状态均计入定义好的预算，不用英文字符/token 比例猜测。
- G04：批量先移除再增加，按最终结果判断；超限或目标不匹配时整批不写。
- G05：相同输入重复整理，当前文件内容和有效提交数不增长；没有变化不生成空提交。
- G06：连续 100 次只出现事实的会话不增加偏好；无旁路 memory.json、溢出 Markdown 或事实库写入。真实事件增长单独计量。

### 内嵌 Git

- G07：在一个已有父 Git 仓库的临时 Cleo 目录下初始化内层仓库，验证内层 toplevel、HEAD 和对象目录均独立。
- G08：父仓库不出现意外 gitlink、.gitmodules 或用户记忆暂存；原本被父仓库跟踪的策略文件保持原有归属。
- G09：制造 sessions、SQLite sidecar、凭据样本、锁和恢复文件，验证 git ls-files 和提交树只有允许文件。不能靠一次 git status 看起来干净判断。
- G10：一次改变只增加一个正常提交，关联处理会话的来源指针可查；未改变不提交。提交说明不复制原文对话或测试正文。
- G11：A 新增语言偏好、B 错改代码偏好、C 新增输出偏好，撤销 B 后保留 A/C；历史展示明确这是撤销，实际项目文件不变。
- G12：Git 缺失、未配置全局作者、提交返回失败、磁盘写失败分别有明确结果；不改用户全局 Git 配置，不把失败标为整理完成。
- G13：无 remote 正常使用；所有初始化、提交和恢复测试禁止隐式 push。

### 发布与恢复

- G14：候选生成后用户手改 MEMORY.md，发布不能以旧版本覆盖，必须发现基线改变。
- G15：两个整理任务同时更新不同项目，以及同一项目；不丢更新、不污染范围、不留下冲突标记。Git 文本可合并不等于语义正确。
- G16：分别在候选生成、文件替换、Git 提交和完成标记之间注入故障；重启重试后有唯一一致版本，无重复提交或虚假完成。
- G17：整理期间新增事件保持待处理，不进入已经固定的快照，也不丢游标。
- G18：先整理新会话、后整理旧会话，旧工作状态不因为整理时间更晚覆盖较新的同事项状态。
- G19：手动删除偏好后正常增量整理不复活；全历史重建的删除语义另列验收，不能把未实现的抑制机制说成已经支持。

### 范围、读取与运行依赖

- G20：productivity/non_productivity、项目 A/B、17214 的不同工作项交叉输入；无跨范围自动提升或误用状态。
- G21：新会话读取到最新已发布偏好，人工改动可被识别；旧事实 SQLite 不成为隐式回退。
- G22：Chat、Codex、Claude、ACP 的同一语义操作获得一致结果；适配器测试与真实客户端验证分开报告。
- G23：保持禁止网络时仍能读偏好、读历史、查看 Git 版本；本地记忆入口不导入 sentence_transformers/torch 或触发模型下载。
- G24：取消、重试与最终成功之后没有残留测试 checkout、工作树、日志和模型样本；真实仓库与共享依赖不被清理。

以上是拟实现的测试清单，当前并没有对应的 24 项生产通过结果。

## 6. 不能用假阳性掩盖错误

语义评分逐命题记录 pass / fail / unverified，并附实际生成文本及来源。允许等义表达；不能用模型自报 confidence 代替验证，也不以“文件更短”作为正确性的代理。

硬错误独立计数：伪造偏好、把一次性要求泛化、泄漏范围、保留被明确否定的旧偏好、把工具指令当用户要求、错误最终状态、引用不存在的来源。某例发生硬错误，即使其他条目正确也不能算整例通过。

还要测有效偏好召回，防止全部返回空记忆获得完美“零污染”成绩。P01/P04/P12 是必须记住的正样本，P02/P03/P10 是必须不记的负样本。

报告分别列偏好召回、错误新增、纠正正确率、重复条目、状态正确率、硬预算拒绝和 Git 一致性，不合成一个掩盖故障的漂亮总分。

## 7. 真实模型实验设计

- 固定输入 fixture 与人工 rubric 的 Git 版本；记录生产提示词/代码提交、provider、模型和实际参数。
- 开发集用这 12 个公开案例调试；另保留至少 6 个不同措辞/顺序的验收案例，在冻结实现后首次运行。不可把开发集提升当泛化证明。
- 小规模先跑 3 个代表案例试通，再完整跑开发集每例至少 3 次；所有失败和重试都计入报告，不只选最好的一次。
- 两个主要 baseline：现有生产记忆流程，以及新 Markdown/Git 流程。若旧流程无法表达新契约，标记为预期不符合，同时报告其实际输出，不伪造可比较分数。
- 语义单步/多步/复核只作为后续实验变量；本轮不锁定额外模型和本地语义 gate。
- 输出文字的主要判定由人工对照固定 rubric；可让另一模型辅助标注，但它不能独自决定通过。未经人工确认的语义结果保持 unverified。
- 真实 provider 失败、限流或无凭据应标记 not_run/error，不能 fallback 到 mock 并报告模型通过。

## 8. 执行和交付顺序

1. 固定本文件与合成对话：先审查测试是否覆盖正确目标。
2. 实现容量与 Markdown 编辑契约，以及内嵌 Git 发布的确定性测试；用真实临时 Git 验证。
3. 改造 DreamAgent 和读取层，迁移旧的事实写入预期；保持原始历史不变。
4. 运行少量真实模型样本，再跑完整语义集和保留集；根据失败调整实现，不随意改真值。
5. 接入 UI/适配器，进行本地 17214 只读预览；确认后执行正式迁移。
6. 完成适用的全套测试、ruff、diff 检查、临时目录清理与最终 PR 说明。

测试的所有可变数据放同一个系统临时任务根目录，pytest basetemp、Git HOME/配置、checkouts、请求输出与日志都在其下。模拟凭据必须明显为假。最终只保留明确的脱敏评测报告；不把真实输入、私有 provider 配置或原始生成日志提交到 PR。
