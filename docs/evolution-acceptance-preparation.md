# 需求准备与验收

[English](evolution-acceptance-preparation.en.md)

进化会话收到修改需求后，保存原文和请求 ID，再读取相关源码，生成并冻结验收案例。
明确的需求直接进入实现；影响实现的歧义会先请用户补充。
每个案例包含对应要求、源码证据、操作条件、预期结果和验证方式。

## 从需求到应用

1. 描述修改需求，确认需要澄清的内容。
2. Cleo 根据冻结案例执行修改，完成后运行编译、构建、回归检查和打包。
3. 检查通过后应用程序，按案例中的操作体验效果。
4. 点击「验收」确认结果，也可提供反馈、继续修改或取消该项验收。备注可选。

构建成功与人工验收分别记录。普通交互案例由用户确认；Dream 格式案例可在独立数据中回放。
案例、源码或构建变化会使旧结果失效，验收记录始终绑定相应版本。

## 恢复与修正

请求原文、澄清记录、案例、执行状态和失败原因会持久化。
刷新或重启后继续读取同一记录，不自动重复发送已提交的编辑任务。
准备失败时可重试原需求；实现中断时可沿用案例继续。

「修正案例」用于调整操作、预期和原因。原案例保留并归档，新案例使用独立 ID。
纯提问在同一会话显示答复，不启动代码修改或构建。

更多操作见[本地进化](cleo-evolution.md)、[直接验收](direct-acceptance.md)和[需求重试与取消验收](acceptance-retry-cancellation.md)。
