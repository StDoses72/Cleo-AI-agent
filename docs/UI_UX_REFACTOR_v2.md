# Cleo 桌面 UI/UX 重构 v2：对标 coding harness

决策记录见 [ADR 0008](adr/0008-single-sidebar-flat-ui-and-review-loop.md)。本文说明这次重构保留了什么、合并了什么、删掉了什么、扩展了什么，以及每一项的理由和依据。

## 1. 目标与方法

目标：在 coding harness 的核心流程上（提出任务 → 观察运行 → 审查改动 → 保留或撤销 → 并行推进多个任务）至少追平 Claude Code、Codex、OpenCode、T3 Code，最好超过它们；同时保留 Cleo 的差异化能力（多 harness、记忆、自我进化），但不让这些能力挤占核心流程。

方法：

- 证据：Cleo 用 mock 客户端在 1440×900 下截取 30 个状态，并提供 `ui/src` 源码；竞品只用官方材料（官网、文档、官方仓库 README 与发布说明中的截图），每条功能说明附来源链接。
- 评审：GPT-6-Astra（Codex CLI，xhigh，只读，关闭 Fast）与 Fable 5.1（xhigh，只读）独立按同一份评分标准打分，并给出差距排序与功能取舍建议。
- 评分标准：11 个维度、加权（附录 A）。持平 = Cleo 加权总分 ≥ 四个竞品中位数，且没有任何维度比该维度最佳竞品低 1.5 分以上；超过 = Cleo 总分 ≥ 最佳竞品。

## 3. 功能取舍

| 原功能 / 界面 | 结论 | 理由 |
|---|---|---|
| 左侧图标栏（对话 / 开发 / 进化 / 记忆 + 设置） | **删除**，并入侧栏 | 四个空间是进入第一个任务前要理解的四种模式；竞品都只有一条线程列表 |
| 对话空间与开发空间各自的侧栏 | **合并**为一条列表的两个分组 | 两类线程互相不可见；后端仍区分空间，点哪个线程就切到哪种 |
| 标题栏中间“项目 — 模式” | **删除** | 与对话标题栏的面包屑重复 |
| 侧栏顶部大标题（“开发任务”） | **删除** | 第三处身份信息，占高度 |
| 侧栏搜索框 | **合并**到命令面板（侧栏“搜索”打开面板） | 面板同时搜命令和全部线程，一个入口 |
| 记忆空间 | **降级**为侧栏入口；三个子视图改为页内标签 | 记忆不是工作流的一个“空间”，是一个库 |
| 进化空间 | **降级**为侧栏入口，保留共享侧栏 | 差异化能力保留可发现性，但不再与核心流程平级 |
| “思考过程”卡 + “工具过程”卡 | **合并**为按时间顺序的单行工作摘要 | 分开的两个桶打乱了“观察→动作”的因果顺序；竞品都是一行 “Worked for 20s” |
| 已完成的计划卡 | **折叠**为一行 | 完成后不该继续占据时间线 |
| 检查器 · 上下文、运行 | **合并**为“概况” | 两个标签都在展示运行状态和参数 |
| 检查器 · 电脑 | **按需显示**（仅桌面版可用时） | 原来在网页/mock 下也显示一个警告页，且新任务常停在这里 |
| 检查器跨线程保持标签 | **删除** | 每个线程默认“变更”（有改动）或“概况” |
| 标题栏“运行记录”“命令面板”图标 | **删除**（运行记录进“更多”菜单，面板用 Ctrl+K 与侧栏“搜索”） | 五个图标里价值最低的两个 |
| 标题栏“撤销项目改动”按钮 | **合并**进改动卡、变更面板和“更多”菜单 | 撤销应该出现在它要撤销的东西旁边 |
| 分支按钮（打开文件夹） | **保留**为分支标签；git 操作移到变更面板的分支行 | 不再让“看起来是分支控件”的按钮去打开资源管理器 |
| 输入区 `@` 按钮（实际打开上下文） | **删除**，换成上下文占用环（点击打开概况） | 图标与行为不符 |
| 设置 · 运行设置 | **删除** | 单会话的模型、推理强度、权限已在输入区；放在全局设置里混淆作用域 |
| 设置 · 当前配置 / 新增连接 / Dream Agent / 子任务路由 / 原生目录 / 更新 / 数据与记忆 | **重组**为 通用（外观、关于与更新）/ 模型与 Agent（模型连接、子任务路由、对话指令、导入）/ 记忆与数据（记忆整理、存储与维护） | Dream Agent 的模型与后台整理是同一件事，放一页；存储与记忆是不同问题，分开 |
| agent 提问全屏模态 | **改为**贴在输入框上方的非模态卡片 | 回答两个选项不该遮住整个应用 |
| 侧栏“演示模式”标记 | **保留**，缩小到底部设置旁 | 只在 mock 下出现 |
| 记忆预览（取全局前三条） | **如实改名**为“最近更新” | 后端还不记录每回合用了哪些记忆，不能冒充“相关记忆” |
| 审批卡、队列/Steer、附件、项目选择、权限选择、斜杠命令、计划、通知卡 | **保留** | 评审认为是现有最好的部分 |

## 4. 新的界面

**侧栏（一条）。** 新任务（Ctrl+N）· 搜索（Ctrl+K）· 记忆（显示待整理数）· 进化；下面是“进行中”（运行中或等待批准/回答的线程，带项目名和状态文字，只在有内容时出现，线程在此期间不在原分组重复出现）、“开发”（按项目分组，项目行显示分支和改动数）、“对话”（分组标题上的“+”新建对话，Ctrl+Shift+N）；底部是设置。行内状态用文字（“运行中”“等待批准”“需要查看”），不只是一个点。

**时间线。** 每个回合一行工作摘要：“已处理 · 运行 2 条命令 · 编辑 3 处 · 1 段思考”，运行中显示当前步骤；展开后按到达顺序列出每段思考和每个工具调用（一行一个，可再展开输出）。计划完成后折叠。回合结束后时间线末尾是改动卡：文件、+/−、“查看改动”“撤销上一轮”。

**详情面板。** 变更 / 文件 / 概况 / 电脑（桌面版）。变更标签自上而下：范围（当前工作区或历史快照）与“撤销上一轮”；分支行（分支、领先/落后计数，提交、推送、创建 PR）；审查意见条（N 条意见、发给 Agent）；文件列表（状态、文件名、目录、+/−，悬停出现单文件撤销）；diff（旧/新两列文件行号，悬停行出现“+”添加审查意见，意见显示在行下）。

**输入区。** 新任务时：项目 · 当前目录/新 worktree · 附件 · 运行方式与模型 · 权限；右侧是上下文占用环和发送/停止。`/` 无匹配时说明原因。

**命令面板与快捷键。** 面板列出全部命令（带快捷键）和最近 5 个线程；输入时先列匹配命令再列匹配线程。Ctrl+K 面板、Ctrl+N 新任务、Ctrl+Shift+N 新对话、Ctrl+B 侧栏、Ctrl+Shift+D 详情面板、Ctrl+, 设置、Ctrl+Tab / Ctrl+Shift+Tab 切换线程。

**通知。** 你没在看的线程运行结束、开始等待批准或回答时发系统通知；命令面板可开关。

**视觉。** 侧栏、对话、详情三栏平铺，以 1px 分隔线区分，面板不再浮起；控件圆角 6px、容器 8–12px，药丸形只留给计数徽标；中性色为主，强调色只用于主操作；正文 14px、控件 13px。

## 5. 扩展了什么、没有扩展什么

扩展（都有真实实现，不是占位按钮）：

- git：逐文件撤销、提交（可提交后推送）、推送、创建 PR、新 worktree 任务（`ui/electron/source-control.mjs`，带真实临时仓库的单元测试）；
- 审查意见：行级评论，汇总成一条指令发给 agent；
- 并行：“进行中”分组、行内状态文字、系统通知、Ctrl+Tab 切换；
- 可发现性：命令面板搜索线程、快捷键提示。

刻意没有做（及原因）：

- 子任务路由的子运行显示为子线程：后端尚未发出父子关系事件，不在 UI 侧伪造；
- 记忆按回合归因（“本回合使用了 3 条记忆”）：同上，需要后端记录；
- `@` 文件模糊搜索：需要可递归的文件索引接口，后续单独做；
- 内置交互式终端：需要 pty 依赖与安全评估，超出本次范围；
- 归档列表、置顶：后端只有“归档并新建”命令，没有列表接口；
- 拖拽分屏、多窗口：收益相对实现成本低，暂缓。

## 6. 验证

- `npm run typecheck`、`npm run test:backend`（含新增 `source-control.test.mjs`，13 项真实临时仓库测试）、`npm run test:context`、`npm run test:evolution` 通过。
- 浏览器与 Electron 冒烟全部通过：`smoke:uiux`（58 项）、`smoke:projects`、`smoke:permissions`、`smoke:concurrency`、`smoke:steering`、`smoke:timing`、`smoke:language`、`smoke:routing`、`smoke:update-settings`、`smoke:computer`、`smoke:history`、`smoke:layout`、`smoke:approvals`、`smoke:inspector`、`smoke`、`smoke:ux`（11 项）、`smoke:memory-sources`、`smoke:tray`、`smoke:evolution-workspace`。`smoke:evolution-ui` 的前三个文件通过，`behavior-review` 见下文。
- 启动真实后端的冒烟需要用 `CLEO_PYTHON` / `CLEO_TEST_PYTHON` 指定装有 Cleo 依赖的解释器（例如仓库的 `.venv`）。不指定时会用 PATH 上的 `python`，本机那个环境的 `openai_codex` 版本过旧，导入就失败。此前“在 `main` 上也失败”的 memory-sources 和 tray 主要是这个原因。
- 重构后的截图与评审结果见第 7 节。

此前记为“在 `main` 上就失败”的检查，逐项处理如下：

- **本次重构留下的过时测试：** 设置页分组后，“数据与记忆”“模型”“原生目录”“Dream Agent”这几个导航按钮已改名或合并，模型子导航也取消了。`memory-sources`、`tray`、`smoke-ux` 和打包冒烟已按新导航更新。发出的消息现在会显示附件标签，`smoke-ux` 的草稿隔离检查和 `smoke` 原来统计整页的标签，结果取决于历史是否已加载，现在只统计输入框里的附件。
- **顺带发现的两个产品问题：**
  - Dream Agent 与后台整理合并到同一页后，在上方停用 Dream Agent，下方的后台整理面板仍按打开时读到的状态显示。现在面板跟随本页最近一次保存的 Dream 设置，未保存的后台设置草稿不受影响。
  - 停用提示原文是“请先在 Dream Agent 页启用”，那个页面已经不存在，改为“请先在上方启用并保存”。
- **原有缺陷：** 验收清单的计数渲染成“0␣␣项待验收”，数字后有两个空格（JSX 空格加上文案开头的空格），`interaction-ui` 因此找不到“0 项待验收”。现在改为由文案占位符拼接数字。
- **Python：** `chat/model_failure.json` 依赖 OpenAI SDK 打印错误的方式：新版 SDK 会把整个响应体字典直接打印出来，界面上也会显示这串字典。现在聊天运行时从 SDK 异常的 `status_code` 和 `body` 中取出提供方自己的错误信息，显示为“Error code: 500 - fake upstream failure”，与 SDK 版本无关，并补了单元测试。golden 无需重录。
- **`behavior-review`：** 它要求“验收清单确认之后才能保存”和“自动检查通过之后才能应用”。这两个限制在 v0.6.0 合并（9a62ea0）时随源码快照一起被移除，合并说明里没有提到。是恢复这两个限制，还是让测试改为接受当前行为，由维护者决定。

## 7. 重构后评分

### 第二轮（第一版重构之后）

| 评审 | Cleo 重构前 | Cleo 重构后 | 竞品中位数 | 最佳竞品 |
|---|---|---|---|---|
| GPT-6-Astra xhigh | 5.61 | 6.64 | 7.36 | 7.46（Codex） |
| Fable 5.1 xhigh | 5.42 | 6.49 | 7.18 | 7.62（Codex） |

结论：+1.03 / +1.07，仍未持平；超出 1.5 分差距的维度从 6–7 个降到 3 个（D3、D6、D11）。评审同时指出了重构本身引入的问题，第三轮全部处理：

- **git 安全**：撤销以 HEAD 判断（已暂存的删除能恢复、已暂存的新文件会取消暂存并删除）；“提交”只暂存并提交任务改动的文件；同一检出目录里还有任务在运行时，所有 git 操作禁用并说明原因；分支行按任务隔离，丢弃过期的状态结果；创建 worktree 防重复提交、显示进行中、用户已离开时不强行切换草稿、跳过已存在的 `cleo/<slug>` 分支；“提交后推送”默认关闭。
- **并行**：worktree 嵌套在来源项目下（分支图标 + worktree 标记），可移除（有未提交改动时 git 拒绝，分支保留）；侧栏顶部拆成“需要你处理”和“运行中”，行内同时显示项目与状态。
- **时间线**：工作摘要在计划、提问、通知处切开，保持决策与动作的先后；计划在最后一步完成时自动折叠；回答下方新增“协作”一行，按后端的任务用量账本显示主任务、子任务与评审分别由哪个 harness/模型完成。
- **审查**：`\ No newline` 不再打乱行号；审查意见绑定行文本，行变化后标为过期；“发给 Agent”直接发送（运行中则排队，保留草稿）；diff 可用键盘选行并添加意见；轻量语法着色。
- **可及性与细节**：详情标签支持方向键；文件标签只在可用时出现；提问卡放行 Ctrl/Cmd 快捷键；Ctrl+/ 打开命令面板；外观页加入桌面通知开关；“导入”改名“Claude / Codex 原生配置”。

### 第三轮

| 评审 | Cleo 基线 | 第二轮 | 第三轮 | 竞品中位数 | 最佳竞品 |
|---|---|---|---|---|---|
| GPT-6-Astra xhigh | 5.61 | 6.64 | 6.92 | 7.36 | 7.46（Codex） |
| Fable 5.1 xhigh | 5.42 | 6.49 | 6.92 | 7.18 | 7.62（Codex） |

结论：两位评审都给 6.92，超过 OpenCode，但仍低于中位数。Fable 认为已没有维度落后最佳竞品超过 1.5 分；Astra 认为 D3（改动审查）、D6（并行）、D11（差异化）仍超出。Astra 用代码与只读 git 验证找到了几处真实缺陷，其中一部分是第三轮自己引入的，第四轮全部修复：

- **检出目录身份**：git 安全按项目 id 判断，同一仓库与其子目录注册成两个项目时互不阻挡；git 操作进行时也不阻止新任务开始。现在按 git 工作树顶层判断，操作进行中拒绝在同一检出目录启动任务。
- **子目录项目**：后端 diff 的路径相对仓库根目录，撤销/提交却在项目目录执行，子目录项目会失败。现在统一从仓库根目录解析。
- **键盘审查**：在评论框里输入 `c` 或回车会被当成审查命令。现在只在 diff 本身获得焦点时响应，关闭评论后焦点回到 diff。
- **审查意见发送**：运行中发送会清空输入框草稿并带走附件；失败时意见已被清除。现在不动草稿，确认送达后才清除。
- 移动任务到别的仓库后分支行不刷新；移除当前选中的 worktree 后选中状态失效；diff 首个 hunk 之前的元数据行被编号；“协作”一行把任务边界分类器当成评审、把用量行数当成子任务数。

### 第四轮改动

除上述修复外，补齐两位评审排名最高、且有真实数据可以支撑的缺口：

- **子任务可见（D6、D11）**：后端在线程上新增可选字段 `parentId` / `routingTaskId`（来自会话 manifest 的 `parent_session_id` / `routing_task_id`）。侧栏把子任务缩进列在父任务下（不再作为互不相关的任务出现），父任务对话末尾列出子任务及其状态与模型，子任务标题栏可一键回到父任务。
- **命令结果（D2）**：后端投影把 Codex 命令的 `exitCode`、`durationMs` 写进工具条目。工具行显示“退出码 1 · 8.4 秒”，失败行默认展开输出；工作摘要按退出码统计失败并给出命令总耗时。
- **记忆使用（D11）**：Cleo 自己的记忆工具调用（检索长期记忆、读取历史对话）在工作摘要里单独计为“查阅记忆 N 次”。每轮自动注入的偏好后端没有逐轮记录，因此不声称。
- **输入框（D5）**：`@` 列出项目文件（`git ls-files`，忽略文件除外），按文件名模糊排序插入路径；模型菜单直接列出当前 harness 的模型（多时可搜索），思考深度改为带标签的分段控件；运行中 Enter 排队、“插入运行”（Ctrl+Enter）立即插入；输入框为空时 Esc 停止。

### 第十轮之后的修复（未评分）

上面四项在第一稿提交之后修复。没有再请评审打分，所以第十轮分数仍是最终分数。

- **意见跟随分支 A → B → A：** Git 行的焦点与轮询回调改为调用最新一次渲染的刷新函数；分支比较改用工作区当前的记录，而不是发出 git 请求时的记录。两者一致时会清除“已对账”标记，再次出现同一不一致时会重新加载。
- **所有仓库在窗口获得焦点时重新读取 Git：** 未推送、不在 GitHub 的分支也包括在内；只有定时轮询仍限于有上游的 GitHub 分支。PR 结果改用独立编号，一次不重新询问 GitHub 的状态读取不再丢弃正在返回的 PR 结果。

- **模型菜单焦点：** “本屏是否已放置焦点”和“菜单把焦点放在哪里”分开记录。焦点一开始就在菜单内时，这一屏的放置机会算作用户已经用掉，之后迟到的模型列表不再移动焦点。
- **160 字符提示：** 只有记忆库里的当前内容比记录更长、确实无法比对时才显示；恰好 160 字且未变化时不再显示。
- **测试：**
  - 原来的分支检查改为在未推送分支上走完 A → B → A，工作区记录只在重新加载时才跟上，并覆盖说明行和“重新检查”。
  - 新增两项检查：焦点一开始就在菜单内的顺序，以及 160 字符边界（包括恰好 160 字、更长、不同、emoji）。
  - “PR 跟随分支”检查原本依赖页面加载时机：第一稿提交的版本重新完整运行时也失败了（55/56）。现在改为装好 mock 之后触发一次窗口焦点，使 Git 行重新读取。
